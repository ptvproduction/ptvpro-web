## Temuan dan perbaikan

1. **Pesan password adalah guard disengaja.** api/auth/login.ts memanggil resolveIdentityByCredentials; di luar test atau saat service-role terpasang resolver mengembalikan pesan tersebut sebelum membaca credential. Helper bcrypt belum dipanggil. Menghapus guard akan mengembalikan jalur identifier-only yang berbahaya. Guard tetap utuh.
2. **Lockout belum diperiksa pada dua helper server.** resolveLiveAccess dan verifyAccountStatusLive sekarang membaca lockout_until dan menolak lock aktif/malformed. Pemeriksaan iat/cutoff diperketat. Ini helper bersama yang juga dipakai modul lain; regression lintas modul tetap lulus, tanpa perubahan Finance151.
3. **Gangguan backend menghapus cookie.** Endpoint session sekarang membedakan backend unavailable (503) dari akses ditolak; keduanya tidak menghapus cookie. Respons tetap tidak memberi izin atau data stale. Cookie yang expired, account nonaktif, cutoff baru atau izin dicabut tetap ditolak. Refresh halaman saat outage dapat menampilkan keadaan belum terautentikasi pada adapter existing; cookie dipertahankan untuk percobaan berikutnya. Tidak memperpanjang sesi atau memberi akses offline.
4. **Input login belum dibatasi.** Parser existing kini mendukung JSON object/raw/stream, batas4096 byte, bentuk field identifier/password saja, identifier maksimum254 karakter dan password maksimum72 byte UTF-8. Bad input400, oversize413, no-store, tanpa cookie baru. Tidak ada password/hash pengguna yang dibaca atau dicetak. Batas platform/deadline request tetap harus diperiksa pada runtime target.
5. **OIDC nonce dan fallback.** Nonce memakai CSPRNG; fallback access-token-only/UserInfo dihapus agar login wajib ID token terverifikasi yang terikat nonce. Tests memakai RSA sintetis nyata untuk valid signature, forged signature, audience/issuer/nonce/expiry/future-iat. Tidak melakukan OAuth nyata. Dokumentasi [Google OIDC](https://developers.google.com/identity/openid-connect/openid-connect) menjadi acuan validasi ini.
6. **Helper RLS Access149 belum lengkap untuk sesi native.** Addendum [SQL152](PTVPRO-ACCESS-152-NATIVE-SESSION-PROPOSAL.sql) terpisah memeriksa trusted auth.uid, numeric exp/iat, session_id milik sub yang masih ada di auth.sessions dan belum melewati not_after, lockout/cutoff, membership dan deny-first. Klaim account_id/profil diabaikan. EXECUTE hanya signature(text) untuk authenticated/service_role; anon/PUBLIC ditutup, tidak membuka SELECT auth.sessions ke klien. Ini tidak mengubah bundle149 atau Finance151. Pemasangan ulang bundle149 lama setelah addendum dapat menimpa helper; urutan/hash harus direview ulang, jangan replay bundle lama sesudah152.
